# Phase 4: 质量验证（详细指南）

生成框架后，用子agent执行3项测试（独立于主agent，避免自评偏差）：

## 4.1 已知测试（Sanity Check）

选3个此人公开表态过的问题，**spawn子agent带着新框架回答**，对比实际立场。
- 方向一致 → 模型有效
- 偏离 → 回溯调整心智模型权重

## 4.2 边缘测试（Edge Case）

选1个此人没公开讨论过但相关的问题，用框架推断。
- 期望结果：「基于模型X和Y的推断，可能...但不确定」
- 不应该斩钉截铁

## 4.3 反模仿测试（Anti-Imitation Check）

用框架写一段100字分析，判断：
- ❌ 没有此人的表达特征？（不应有）
- ✅ 是中性结构化语言？（应该有）
- ✅ 不是通用AI味鸡汤？（应该有）
- ✅ 不是原话拼凑？（应该有）

## 4.4 通过标准

| 检查项 | 通过标准 | 不通过信号 |
|--------|---------|-----------|
| 心智模型数量 | 3-7个，每个有来源证据 | <3或>10 |
| 每个模型的局限性 | 明确写出失效条件 | 只写优点 |
| 语言风格 | 中性、结构化、无个人语气 | 像某个人的口吻 |
| 诚实边界 | 至少3条具体局限 | 只有「不能替代本人」 |
| 内在张力 | 至少2对矛盾 | 观点高度一致（太假） |
| 一手来源占比 | >50% | 主要依赖二手转述 |
| **反模仿检查** | 无第一人称、无特定措辞、无修辞模仿 | 读起来像某个人在说话 |

验证通过 → 交付。不通过 → 标注薄弱环节，回到Phase 2迭代。
**迭代上限**：Phase 2→4最多循环2次。如果2轮后仍有不通过项，在诚实边界中标注薄弱维度，交付当前最优版本而非无限打磨。

**展示验证结果给用户确认后才算完成。**
